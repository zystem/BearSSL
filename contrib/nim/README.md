# Using this fork from Nim

Two small patches, tried on 2026-11-19 (nim-bearssl 0.3.1, nim-grpc 0.7.0 at the time):

- `nim-bearssl-tls13-sources.patch`: the new C files of this fork must be
  compiled by the `bearssl` Nim package (add them to `bearssl/abi/bearssl_ssl.nim`),
  and its `csources/src` and `csources/inc` replaced by this repository's `src`
  and `inc`.
- `nim-grpc-gtls-tls13.patch`: `src/nimgrpc/tls/gtls.c` of nim-grpc offers
  TLS 1.3 (versions `BR_TLS12` to `BR_TLS13`, the three TLS 1.3 suites in front of
  the TLS 1.2 ones), its server policy wrapper forwards `choose13` and `do_sign13`,
  and session resumption works with TLS 1.3: the client keeps the session when
  the ticket has arrived (with the first records after the handshake, so
  `keep_session` is also called from `gtls_push_records`), and `gtls_resumed`
  asks the engine (`br_ssl_engine_tls13_resumed`) instead of comparing session IDs.

nim-grpc points at a checkout of the package with `NIM_BEARSSL=<dir>`.

Result (2026-11-20, nim-grpc 0.7.0, fork at the commit of `tls13-resume`): all 23
other test programs pass, `tests/ttls.nim` passes 29 of 29 checks, including the session
resumption ones, over TLS 1.3 with ALPN h2; grpc-go interoperability (TLS and mutual TLS) was run
before resumption was added (see `TLS13-PLAN.md`).

Known gaps (step 8 of `TLS13-PLAN.md`): the Nim mirrors of the C structures in
`bearssl/abi` (generated by c2nim) were not regenerated, so Nim code that uses the
engine structures directly, instead of only the C API, must not be built against
this fork before that is done (the engine context and `br_ssl_session_parameters` changed);
the casts of function pointers in the new vtables (`ssl_rec13_*`, the engine hooks) are not
wrapped as the nim-bearssl patch does for the old ones (needed for CFI or `-fsanitize=function`).
